# Anti-Slop Audit 001 — MCP-Studio client UI

- Date: 2026-11-02
- Scope: `client/src/**`, `client/index.html`, `client/tailwind.config.js`, `client/src/index.css`
- Mode: AFTER (audit first, fix only approved numbers)
- Rule tiers: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW

## Findings

### HIGH — Hard Gate

1. **R-36 — Fabricated compliance claims.** `BenchmarkView.tsx:277-317` renders a "MCP Protocol Conformance" card with four hardcoded green-check items ("JSON-RPC 2.0 Compliance", "Tools Schema Draft-07", ...). The app only measures roundtrip latency; nothing verifies these claims. Every visit shows a passing audit that never ran.
2. **R-25 — Text below WCAG AA.** `text-slate-500` (#64748b) on `surface-950` (#020617) is ≈4.2:1, under the 4.5:1 minimum. It is the default color for 10–12px descriptive text across ~60 usages in every view (tool descriptions, hints, metadata), plus `placeholder-slate-500` on all inputs. `text-slate-600` icons on dark surfaces are ≈2.7:1 (below the 3:1 non-text minimum where they carry meaning).
3. **R-32 — No visible keyboard focus on most custom controls.** Only one `focus-visible` style exists in the whole client (Sidebar). Tool/resource/prompt list buttons (`ToolsView.tsx:181-207`, `PromptsView.tsx:117-143`, `ResourcesView`), result tabs (`ToolsView.tsx:291-304`), history chips (`ToolsView.tsx:390-412`), and traffic rows have no focus indicator; keyboard users cannot see where they are.
4. **R-03 — No responsive/mobile layout.** The shell is a fixed three-pane IDE (`Sidebar w-60` + list `w-72` + form `w-96`); below ~1024px the panes squeeze/overflow with no collapse, stacking, or drawer behavior. Navbar has partial `sm:` handling only. On a phone the main views are unusable.
5. **R-37 — Design built without direction.** No `DESIGN.md` or stated brand direction exists; the indigo-on-slate dark dashboard is the unfiltered default look. Per R-37 this is a draft, not a deliverable. Fix starts with writing a direction (palette rationale, type rationale, dials, identity motif) and applying it.
6. **R-27 — Missing app-level error state.** When the backend is unreachable, `App.tsx loadServers()` only logs to console; the user gets empty panes with no explanation. Per-view empty/loading states exist, but the "cannot reach backend" state (distinct from "no tools") is not shown anywhere.

### MEDIUM — Purpose-Gate

7. **R-04 — Generic "AI sparkle" icon as default.** `Sparkles` is the Prompts tab icon (Sidebar), every prompt list item (PromptsView), the chat empty-state avatar (ChatSandboxView:379-380), the command-palette Prompts entry, and the ServerModal heading icon. Sparkle/magic glyphs are the canonical AI-slop icon.
8. **R-04 — Icon set chosen by library default.** All icons come from lucide-react thin-stroke defaults with no written relevance for generic glyphs (Wrench for every tool row, FolderArchive, Zap, Bot). Relevance is asserted, not argued.
9. **R-01 — Decorative gradients without purpose.** The brand mark (Navbar:50) and chat avatar (ChatSandboxView:379) use `bg-gradient-to-br from-brand-600 to-brand-400` purely as decoration; a flat mark would carry the same hierarchy.
10. **R-29 — Palette exceeds the system.** Active hues: indigo (brand) + emerald + rose + amber + purple (PromptsView role chips only, `purple-950/15`, `text-purple-400`). Purple is a one-off outside any system.
11. **R-06 — Typeface without a written reason.** Inter is the default AI sans; no rationale recorded. JetBrains Mono for code surfaces is justified (dev tool), but `section-label` applies uppercase + wide tracking as a blanket style.
12. **R-09 — Functionless capsule badges.** "IDE" pill in the Navbar (uppercase, tinted border) restates what the brand line already says; "AI" pill on the sidebar chat item is decoration.
13. **R-39 — Icon-only buttons named by `title` only.** 23 `title=` usages supply accessible names for icon buttons (Power, Refresh, Copy, Close...). `title` is an unreliable name source for assistive tech; `aria-label` (or visually-hidden text) is required.
14. **R-39 — `prefers-reduced-motion` ignored.** Zero handling in the client: `animate-spin`, `animate-pulse`, and `transition-all duration-500` bars run regardless of the OS setting.
15. **R-07 — Background grid without identity purpose.** `index.css .bg-grid` defines a 24px blueprint grid "for hero areas"; a dashboard has no hero, and no identity reason is recorded for the texture.

### LOW — Quality Locks

16. **R-31 — No decision is written down.** No DESIGN.md, no token doc, no one-line reasons for palette, type, radius, or spacing; decisions are unverifiable by design.
17. **R-20 — No identity motif.** Swap the logo and product name and the UI reads as a generic dark indigo dashboard; nothing repeats that could only belong to this product (the core "sloppy" perception).
18. **R-39 — Wrong shortcut symbol.** Navbar shows `⌘K` unconditionally while the binding is Ctrl+K on Windows/Linux (misleading affordance).
19. **R-23 — Assumed brand assets.** Logo is a stock Boxes glyph in a gradient tile; favicon is a stock lucide path. Honest placeholders are acceptable, but they were never declared as placeholders.
20. **R-02 — Em dashes in source comments.** `chat-service.ts:532`, `api.ts:36`, `TrafficView.tsx:26` (comments are not UI copy, so out of the strict scope; listed for hygiene).
21. **R-21/R-34 — Dark-only theme with hardcoded colors.** A dark default is legitimate for a developer tool, but the reason is not recorded and colors are hardcoded (`surface-*` literals everywhere), so a future light theme means a rewrite rather than a token swap.

## Notes

- The `ui-ux-pro-max --design-system` run for this product returned an off-target pattern (FAQ/documentation landing) and was rejected; the fix phase will use targeted domain searches (ux, typography, color, react) instead.
- No changes were made to any file during this audit.
